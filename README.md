# FunPay для Android

Неофициальный клиент [funpay.com](https://funpay.com) для Android на WebView:
сайт открывается внутри приложения, поверх него — нативная нижняя навигация
и уведомления о новых сообщениях.

Текущая версия — **1.0.0**.

## Возможности

- Сайт funpay.com внутри приложения, сессия и cookies сохраняются между запусками.
- Уведомления о новых сообщениях в чатах: имя собеседника, текст сообщения,
  переход сразу в нужный диалог по тапу.
- Запуск без отдельной SplashActivity: заставка рисуется системой через
  `windowBackground`, пока приложение инициализируется.
- Нижняя навигация: Главная, Чаты, Заказы, Профиль, Настройки.
- Кастомный экран «нет соединения» вместо стандартной ошибки WebView.
- Автовосстановление фоновых проверок после перезагрузки устройства.

## Уведомления

У FunPay нет публичного push-API, поэтому приложение периодически запрашивает
страницу `https://funpay.com/chat/` с cookie вашей сессии и сравнивает
состояние диалогов с предыдущим.

Работают три механизма, все используют один и тот же детектор, поэтому
дублей нет:

| Механизм | Когда работает | Интервал |
|---|---|---|
| JS-наблюдатель в WebView | приложение открыто | ~1 с |
| Foreground-сервис | приложение в фоне | 60 с (настраивается) |
| WorkManager | страховка, если сервис остановлен | 15–60 мин |

Новым сообщением считается рост `data-node-msg` у диалога при флаге `unread`
и `data-node-msg > data-user-msg`. Прочитанные чаты уведомлений не вызывают.

Ограничения:

- На Android 13+ нужно разрешение на уведомления (запрашивается при первом запуске).
- Мгновенный режим показывает постоянное тихое уведомление «FunPay следит
  за сообщениями» — это требование Android к долгой фоновой работе.
- Некоторые прошивки (Xiaomi, Huawei, Samsung) останавливают фоновые сервисы.
  В таком случае приложению нужно разрешить автозапуск и снять ограничение
  расхода батареи.
- Разбор HTML зависит от вёрстки сайта. Если FunPay её изменит, править нужно
  только `FunPayChecker` и `PageScripts.UNREAD_WATCHER`.
- Сессия должна быть активна: после смены пароля или выхода из аккаунта
  на сайте проверки перестанут видеть сообщения, пока вы снова не войдёте.

## Сборка

Требования: JDK 17, Android SDK 34.

```bash
./gradlew assembleDebug
./gradlew assembleRelease
```

### Подпись release-сборки

Создайте в корне проекта `keystore.properties` (файл в `.gitignore`):

```properties
storeFile=release.keystore
storePassword=пароль-хранилища
keyAlias=funpay
keyPassword=пароль-ключа
```

Если файла нет, release-APK подписывается debug-ключом: он устанавливается
на устройство, но не подходит для публикации.

## Release через GitHub Actions

Workflow `.github/workflows/release.yml` собирает APK и прикрепляет его
к GitHub Release при пуше тега `v*`.

```bash
git tag v1.0.0
git push origin v1.0.0
```

Ручной запуск без релиза: Actions → Build release APK → Run workflow
(APK доступен в артефактах сборки).

Для подписи добавьте в Settings → Secrets and variables → Actions:

| Секрет | Значение |
|---|---|
| `KEYSTORE_BASE64` | `base64 -w0 release.keystore` |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | имя ключа |
| `KEY_PASSWORD` | пароль ключа |

Без этих секретов сборка тоже пройдёт, но APK будет подписан debug-ключом.

## Структура

```
app/src/main/java/com/funpay/app/
├── FunPayApplication.kt        Application, каналы уведомлений, WorkManager
├── ui/main/MainActivity.kt     WebView, нижняя навигация, JS-мост
├── ui/settings/                настройки уведомлений и данных
├── ui/webview/                 WebViewClient, JS-мост, внедряемые скрипты
├── notifications/              проверка /chat/, дедупликация, сервис, Worker
└── utils/                      cookies, сеть, настройки
```
